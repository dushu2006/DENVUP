# Assets

Every image, icon and mark used by the DENVUP site, where it comes from, and
how it is regenerated.

Two rules govern this file:

1. **Nothing here is a placeholder.** There is no grey box and no stock
   photograph. Every image is either derived from the supplied brand files or
   drawn by a script in this repository.
2. **Everything is reproducible.** Each output has a command. Running the
   command again produces the same file.

---

## 1. The brand files

These are the two files supplied with the project. **They are never modified,
redrawn, traced or substituted.** The site uses their exact pixels.

| File | Size | What it is |
| --- | --- | --- |
| `logo_color.png` | 1342 × 1172 | The ember → amber emblem |
| `logo_black.png` | 1254 × 1254 | The carbon-black version of the same emblem |

**An important fact about them:** neither file contains a wordmark. Both are
the emblem only. The "DENVUP" wordmark on the site is *typeset* in Archivo
Variable — it is not traced from artwork, and the supplied emblem is never
redrawn to look like a wordmark.

## 2. The derived icons and social images

Generated by `scripts/build-assets.py`. Every output is a crop, a scale or a
composite of the original pixels, so the silhouette and proportions of the
supplied logo are preserved exactly.

```bash
python3 scripts/build-assets.py
```

## 3. The original artwork

Seven pieces, one art direction, drawn by `scripts/build-art.py`.

```bash
python3 scripts/build-art.py
```

The script is seeded, so the output is byte-identical between runs. Every
piece is 1600 × 900 JPEG.

**The art direction.** A paper ground (`#edecea`) with a fine grain; a
blueprint grid of ember hairlines; one large geometric mass; one small
accent shape placed off the centre; a soft vertical light gradient so the
field is never flat. The palette is the site's own: paper, ink, ember,
signal. There are no gradients between two hues and no translucent colours
crossing, because two translucent colours make mud.

| File | The idea | Where it appears |
| --- | --- | --- |
| `public/art/service-web-design.jpg` | A page under construction: a large ink column on a blueprint, with one signal square | The web design detail page |
| `public/art/service-ai-solutions.jpg` | A jittered field of nodes, one of them selected, and the paths that answer it | The AI solutions detail page |
| `public/art/service-business-integrations.jpg` | Named systems drawn as bands, with the flow between them | The business integrations detail page |
| `public/art/service-creative-experiences.jpg` | Layered planes turning in space | The creative experiences detail page |
| `public/art/service-automation.jpg` | A token travelling a track into a processor | The automation detail page |
| `public/art/concepts-mask.jpg` | A circle cut out of an ink field | The concepts page and the image-mask transition |
| `public/art/plate-01.jpg` | The studio plate: the real emblem set on a tipped signal-blue plane inside a broken ink orbit, with a type-specimen column and a sampled lattice alongside | The home page — the one large image on the site, full-bleed between the manifesto title and its argument |

Each is used at `width="1600" height="900"` with `decoding="async"`, and
each carries a real `alt` that names the service it belongs to.

**The plate is the only piece that contains the brand asset.** `plate-01.jpg`
composites the supplied `logo_color.png` (cropped to its alpha bounding box,
scaled to 560 px) into a drawn composition. The emblem itself is never
redrawn, recoloured or distorted: it is the file that was handed over, placed
on a plane.

**Where each piece is used at a glance.**

| File | Also used as |
| --- | --- |
| `public/art/service-*.jpg` | A small plate in the matching step of the home page's services chapter, next to the live diagram |
| `public/art/plate-01.jpg` | The home page's manifesto chapter, full-bleed, above the fold of that chapter |

## 4. The portraits — slots, not placeholders

**No photographs were supplied, and none were invented.** The four people in
the studio each have a portrait *slot*: a monogram, drawn in the studio's own
emblem treatment, inside a frame that reserves the photograph's exact box.

The moment a real photograph is supplied, the slot picks it up. No layout
change, no second template, no missing-asset error.

Drop the files into `public/portraits/` with these names:

| File name | Person |
| --- | --- |
| `t-dusyanth.jpg` | T. Dusyanth |
| `m-nanda-kishore.jpg` | M. Nanda Kishore |
| `k-v-sai-prashanth.jpg` | K. V. Sai Prashanth |
| `p-venkatesh.jpg` | P. Venkatesh |

The swap is handled by `src/sections/portraits.ts`. It works on both the home
chapter's team strip and the studio route's people list.

**Until those files exist**, the monogram is what the visitor sees, and that
is the honest state of things.

## 5. The type

| Family | Source | Licence | Use |
| --- | --- | --- | --- |
| **Archivo Variable** (weight + width axes) | `@fontsource-variable/archivo` — self-hosted, shipped in the build | OFL 1.1 | Display and body type |
| **JetBrains Mono Variable** | `@fontsource-variable/jetbrains-mono` — self-hosted, shipped in the build | OFL 1.1 | Labels, indices, figures, code |

Both are bundled. **No font is fetched from a third party at runtime**, so
there is no external request, no privacy question and no layout shift from a
late font.

## 6. What is drawn in the browser, not stored

A large part of this site's visual identity is not an image at all. It is
drawn by code, which is why it can be responsive, themeable, and
reduced-motion aware.

| What | Where | What it is |
| --- | --- | --- |
| The stage | `src/core/stage.ts` | One canvas behind the whole site: a particle field whose colour, camera and shapes change per chapter and per route |
| The grain | `src/shell/shell-before.html` | A fixed noise layer, generated as a data URI |
| The brand chapter's field | `src/sections/mark.ts` | The emblem's own geometry redrawn as a particle field |
| The capability atlas | `src/sections/atlas.ts` | A plotted SVG map with drawn connectors |
| The five service signatures | `src/sections/service-visuals.ts` | The wireframe, the node network, the flow, the layers, the token |
| The workflow diagram | `src/sections/service-detail.ts` | An animated SVG that draws itself and travels a marker along the flow |
| The cursor | `src/core/shell.ts` | A dot and a ring, drawn in the DOM |
| The 149 technique demos | `src/demos/*` | Every one is live code, not a recording |
